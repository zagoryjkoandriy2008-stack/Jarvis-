# JARVIS Windows — двосторонній зв'язок, файли, макроси, AI-екран (без інсталяційних збірок)

Гілка: \`feature/windows-companion-extensions-20261122\`.
Цей документ — *чекліст перевірок*, а не доказ роботи на фізичних пристроях.
Не запускаємо workflow публікації EXE/APK/ZIP без окремої команди власника.

## 1. Передумови (один раз)
- [ ] On-premise Windows 10/11 x64: JARVIS відкритий, Worker URL рівно HTTPS \`/chat\`, секрет Worker у DPAPI.
- [ ] Pixel 9: відповідний Android-код, JARVIS Relay добровільно увімкнений.
- [ ] Watch7: сумісна версія, Wear Data Layer і підключений до Pixel компаньйон.
- [ ] Cloudflare Worker розгорнутий із новими \`/device/v1/files/*\` — **не розгортати автоматично**.
- [ ] У Windows \`EnableDeviceRelay\` увімкнений; \`EnableScreenShare\` і \`EnableRemoteControl\` за замовчуванням лишаються OFF.
- [ ] Дві різні мережі: Pixel на мобільному інтернеті, ПК на Wi‑Fi (не лише домашня локальна мережа).

## 2. Екран ПК і дистанційний ввід на Pixel (регресія)
- [ ] «Покажи екран комп'ютера»: Pixel отримує кадри, Windows показує видимий червоний індикатор.
- [ ] Перед дозволом власника Windows будь-який клік/ввід відхиляється.
- [ ] Після локального дозволу: одинарний/подвійний/правий клік, довгий тап, drag, scroll, літери українською/англійською, Esc/Enter/Tab/Backspace працюють.
- [ ] Меню і панель завдань ПК не перекриті інструментами телефона; координати країв не зсунуті.
- [ ] Відмова/завершення сеансу/вимкнення Windows дозволу припиняє кліки та прибирає останній кадр. Старий session ID не відновлюється.
- [ ] Pixel без мережі, Worker 503, 401, слабка мережа: без зависань чи повторного виконання небезпечних дій.
- [ ] Windows UAC/login не обходяться; це обмеження системи.

## 3. Голос, Watch7 ↔ Pixel ↔ Windows
- [ ] Watch7 «комп'ютер» → «відкрий блокнот» → Windows повідомляє успішну дію; друга команда не закриває JARVIS на годиннику.
- [ ] Watch7 «стан комп'ютера»: показано справжні CPU, RAM, системний диск, без вигаданих температур.
- [ ] Pixel режим «комп'ютер» → «статус пк»: той самий звіт; режим «телефон» не запускає Windows-команди.
- [ ] Без зв'язку Watch7→Pixel або Pixel→Worker — чесне повідомлення про відсутність ACK, без неправдивого підтвердження.
- [ ] Невідомий/повторний remote ID не виконує небезпечну дію вдруге, журнал отримання зберігає at-most-once.
- [ ] Віддалене «напиши пароль», «натисни підтвердити», «проаналізуй екран» відхиляється; не обходить підтвердження власника ПК.
- [ ] Локальний Ctrl+Shift+J та кнопка мікрофона працюють зі встановленим SAPI STT; якщо українського пакета немає, користувач має текстове введення.

## 4. ШІ та аналіз екрана
- [ ] Команда «проаналізуй екран» або кнопка працює **локально**, навіть якщо перед тим вибрано ціль Watch7.
- [ ] Натиснути «Ні»: немає захоплення JPEG та POST /chat.
- [ ] Натиснути «Так»: зроблено лише один JPEG основного монітора; обмеження 220 КБ; в AI приходить input_image через Worker.
- [ ] Відповідь пояснює вміст кадру, але не виконує автоматичних кліків.
- [ ] Без Worker/токена/мережі показується помилка, без прихованої повторної передачі.
- [ ] Скріншот не записується в \`%LOCALAPPDATA%\Jarvis.Windows\`, журнал або ChatHistory як base64.
- [ ] Перевірити під час відкриття паролів: діалог згоди попереджає про потенційний витік даних; користувач може відмовитися.

## 5. Windows макроси
- [ ] «Робочий режим» із діями \`відкрий блокнот\`, \`пауза 2 секунди\`, \`гучність 35\` виконується послідовно.
- [ ] Той самий збережений макрос із Watch7/Pixel виконується в Windows за увімкненого Relay.
- [ ] Невідомий макрос з Watch7 відхиляється; чужі скрипти, shell, AI-розпорядження не виконуються.
- [ ] Більше восьми дій, «пауза 11 секунд», «напиши пароль» — відхилення під час збереження.
- [ ] Зупинка JARVIS/скасування виконує \`CancellationToken\` між кроками.

## 6. Файли Windows ↔ Pixel
- [ ] Windows → Pixel: вибрати TXT/PNG/ZIP до 1 МіБ; Pixel «📂 Файли ПК» → «Перевірити файл» → системний Save As → файл байт-у-байт.
- [ ] Pixel → Windows: Pixel «📤 Вибрати файл...» → системний вибір → Windows «📥 Отримати з Pixel» → системний Save As → файл байт-у-байт.
- [ ] Після успішного збереження ACK видаляє вміст тимчасового сховища.
- [ ] Якщо користувач скасує Save As, ACK не надсилається.
- [ ] Спроба другого файлу в той самий напрямок до отримання першого повертає 409 без заміни.
- [ ] Після 120 секунд файл недоступний; при перезапуску Durable Object може зникнути ще раніше. Обидва напрямки ізольовані.
- [ ] Порожній файл, файл >1 МіБ, небезпечне ім'я, неправильний MIME/UUID та переповнений streaming body відхиляються.
- [ ] Додаток не відкриває і не запускає переданий APK/EXE. Відсутнє сканування на шкідливий вміст; ці файли не відкривати без перевірки.
- [ ] Немає автоматичного доступу до папок чи контактів. Worker має лише персональний bearer; **E2EE і окремого попристроєвого pairing поки немає**.

## 7. Моніторинг і повторна регресія
- [ ] CPU і RAM порівняти з Диспетчером завдань Windows (невелика різниця через вимірювання у різні моменти очікувана).
- [ ] Вільне місце C: порівняти з Провідником; на системах, де Windows не на C:, використати фактичний системний диск.
- [ ] Вимкнути Wi-Fi на Pixel, повторити віддалену команду: має бути явний збій без прихованого повтору; знову під'єднати й перевірити.
- [ ] Скасувати AI-аналіз/віддалене керування/отримання файла тричі поспіль, кожного разу перевірити, що немає залишкової активної сесії або повторного завантаження.
- [ ] Закрити JARVIS Windows під час файлообміну: після перезапуску не відкриває файлів автоматично й не ввімкне трансляцію екрана без дозволу.
