# JARVIS Windows ↔ Pixel ↔ Watch7 — реалізація P0–P8

Виконання відбувається у гілці `feature/jarvis-cross-device-p0-p8-20261122`,
створеній від `feature/windows-companion-extensions-20261122`. Це код, не збірка APK/EXE,
не деплой Worker, не підтвердження фізичної працездатності.

## Безпека і порядок

- [x] P0: типізовані команди v2, TTL, явні статуси, класи прав, заборона довільного shell.
- [ ] P0: повний криптографічний pairing Windows↔Pixel, підтвердження на обох
  пристроях, ключі в Keystore/DPAPI, підпис запитів, серверна перевірка,
  відкликання пристроїв і міграція Relay. **Не вважати поточний спільний bearer
  безпечним pairing. Новий v2 контракт поки НЕ підключений до виконання.**
- [x] P1 (код): Windows tray, опційний автозапуск HKCU і захист від дублювання.
- [ ] P1: фізична Windows перевірка sleep/resume, трея й автозапуску.
- [x] P2 (частково): heartbeat/status з TTL, Windows текстова панель.
- [ ] P2: криптографічні ключі та повна панель Pixel/Watch.
- [x] P3 (частково): додані Windows команди та локальні підтвердження, старий ACK збережено.
- [ ] P3: фізичний тест Watch7 та багатоступеневі стани accepted/running/completed.
- [x] P4 (частково): опційний SAPI wake word за наявності Windows мовного пакета.
- [ ] P4: whisper.cpp, VAD і перевірена українська модель.
- [x] P5 (частково): макроси v2, умовний рушій, repeat, розклад, редактор, pure-тести.
- [ ] P5: подійні тригери мережі/програм/підключень, безпечний UIA editor.
- [x] P6 (частково): AI Desktop із UIA, локальними згодами, вимкненим JPEG за замовчуванням, маршрутизацією AI Worker.
- [ ] P6: hardware-тести Windows, підтримка вибору моделей у GUI, P0 pairing.
- [x] P7 (частково): локальний потоковий AES-GCM chunk codec + короткоживучий текстовий контракт.
- [ ] P7: реальна мережа R2/E2EE handshake, resume, Android SAF і відправка clipboard.
- [x] P8 (частково): Magic Packet із Pixel по Wi-Fi, конфігуратор MAC/broadcast, команди Watch7, Java тести.
- [ ] P8: підтвердження запуску через heartbeat, WAN gateway, фізичний тест BIOS/NIC.

Правило: автоматизовані тести для кожного етапу; повторний негативний тест
після виправлення. Складання інсталяційних APK, EXE, публікації та merge — тільки
за окремим дорученням власника.
