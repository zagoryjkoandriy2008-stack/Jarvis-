# JARVIS Windows ↔ Pixel ↔ Galaxy Watch7 — поетапна реалізація P0–P8

Гілка: `feature/jarvis-cross-device-p0-p8-20261122` (чернетка PR #15),
база: `feature/windows-companion-extensions-20261122` (чернетка PR #14).
**Жодного APK, EXE, розгортання Worker або merge у main не запускали.**
Перевірки коду ≠ перевірки на реальних пристроях.

## Стан у вихідному коді

- [x] **P0 — частково.** Ключ P-256 у Windows DPAPI й Pixel Android Keystore; одноразовий
  код, підписане підтвердження власника, fingerprint, відкликання; підписані
  запити команд v2, TTL, дедуп, стани accepted/running/completed/failed/unknown;
  окремі серверні й локальні Windows-дозволи для readOnly/media/apps/locks/Watch.
  Windows повторно перевіряє підписаний серверний дозвіл після отримання
  команди перед її виконанням, а для системного блокування/монітора ще раз
  ПІСЛЯ локального діалогу підтвердження. Відкликання під час черги або
  затягнутого підтвердження блокує дію, без silent downgrade до v1.
  Після відкликання Pixel сервер блокує весь Relay v1, включно з файлами/екраном.
- [ ] **P0 — решта.** Перевірка pairing на реальному Windows/Pixel; криптографічний
  сеансовий обмін ключами ECDH/HKDF для E2EE файлів, ізольований сеансовий grant,
  повна міграція PC→Pixel/Watch і файлів із v1. V1 активний для сумісності, доки
  власник не відкличе його через відповідну дію.
- [x] **P1 — частково.** Системний трей, HKCU автозапуск за згодою, єдиний екземпляр,
  показ уже запущеного через локальний pipe, backoff з jitter.
- [ ] **P1 — решта.** Фізичні тести sleep/resume, мікрофона, вимкнення трея і процесу.
- [x] **P2 — частково.** Підписаний heartbeat PC/Pixel і TTL онлайн, центр пристроїв
  на Pixel, статус у Windows. Для Watch7 використано стан Wear Data Layer, не
  вигаданий серверний heartbeat програми.
- [x] **P2 — частково.** Компактна панель Watch7: заряд і реальний Wear
  Data Layer, стан Windows із Pixel, вихід без скидання режиму JARVIS.
  Повторна авторизація команди після передачі в чергу вже в коді.
- [ ] **P2 — решта.** Фізичні тести Watch7 і розширений журнал подій
  без приватних даних; перевірка revoke безпосередньо перед дією.
- [x] **P3 — частково.** Нормалізовані українські фрази стану/медіа/гучності,
  дозвіл на перевірені програми, блокування Windows і монітора лише з підтвердженням,
  маршрут Watch→Pixel→Worker→Windows; результат не плутається з ACK черги.
- [ ] **P3 — решта.** Реальні 20 команд Watch7, друга команда без закриття,
  2 мережі, перевірка TTS і відхилення безпечних/заборонених команд.
- [x] **P4 — частково.** Локальний SAPI wake phrase за явним дозволом, fallback
  при відсутності Windows recognizer, без передавання standby-аудіо.
- [ ] **P4 — решта.** whisper.cpp, VAD, справжня українська офлайн-модель
  і 50 фізичних тестів на мікрофонах та з музикою.
- [x] **P5 — частково.** Макроси v2, розклад, умови, if/else, bounded repeat,
  стоп/тайм-аут, візуальний редактор, сумісність із v1. Тепер також тригери
  network.online/network.offline через Windows NetworkChange (без polling),
  а також app.active:process через WinEventHook та app.start:process через
  події WMI Win32_ProcessStartTrace. Обидва слухачі працюють лише коли
  власник зберіг відповідний макрос, без постійного опитування. Зберігаємо LastRun/ID під час редагування, тому
  cooldown не обходиться повторним збереженням макросу. П'ять
  шаблонів для заповнення редактора не запускаються автоматично;
  планувальник перевіряє всі due-макроси, а не лише перший.
- [ ] **P5 — решта.** Тригери підключення пристроїв,
  геофенс і безпечне делегування Watch7. Фізично перевірити події мережі,
  активні вікна, повторний запуск після sleep/resume і cooldown.
  Макроси мають глобальний ліміт 2 хвилини; linked CancellationToken
  тепер передається всередину кожного кроку.
- [x] **P6 — частково.** Локальна згода, UI Automation first, типізовані дії,
  15 кроків, перевірка після виконання, STOP, opt-in JPEG, резервний API
  через Cloudflare Secrets, fail-closed на невідому дію.
- [ ] **P6 — решта.** Повні UX/UIA/DPI фізичні тести, mask/private apps,
  ручний вибір моделей та вимір витрат/бюджету.
- [x] **P7 — частково.** Потоковий codec AES-256-GCM по 1 МіБ,
  SHA-256, обробка пошкодження, короткий TTL текстового буфера.
- [ ] **P7 — решта.** R2 multipart, resume, ECDH E2EE, SAF Pixel,
  actual clipboard bridge та фізичні 10/100/1024 МіБ тести.
- [x] **P8 — частково.** Magic Packet із Pixel, перехоплення команди Watch7,
  приватний IPv4 broadcast, MAC, перевірка broadcast на поточній підмережі Wi-Fi,
  прив'язка UDP до активної мережі. Після Magic Packet Pixel тепер
  перевіряє свіжий ПІДПИСАНИЙ heartbeat Windows (не плутає зі старим online).
  Відповідь Watch7 приходить після перевірки або як «не підтверджено».
- [ ] **P8 — решта.** Реально перевірити НОВИЙ heartbeat після пробудження
  на конкретному ПК; WAN gateway/VPN, BIOS/NIC/Power тести не виконані.

## Правильне підключення після окремої команди на збірку й деплой

1. Налаштувати Worker Secrets; не надсилати ключі в чат. **Worker має бути розгорнутий
   окремою командою** перед будь-якими реальними тестами мережі.
2. На Windows увімкнути Relay; вкладка Пристрої → створити ID і 7-значний код.
3. На Pixel налаштувати той самий Worker URL/токен; Пристрої →
   Спарювання Windows: ввести ID та код, показати fingerprint.
4. На Windows перевірити fingerprint → підтвердити Pixel. Прочитати та
   зберегти потрібні гранти: стан, медіа, програми, системні дії, Watch7.
5. Лише тоді вручну активувати «підписаний Relay v2» і на Pixel, і Windows.
   Якщо він не налаштований — не робити автоматичного downgrade до v1.
6. На Watch7 перейти у режим «комп'ютер». Перевірити «який стан комп'ютера»,
   «наступна пісня на ПК», «зроби гучність ПК 40», підтвердити блокування
   на самому Windows. Вихід — «годинник» або «телефон».
7. При явному **відкликанні** Pixel Worker блокує також усі старі v1 маршрути.
   Це зупинить legacy-передавання файлів і старі PC→Pixel Finance/нотатки
   до завершення міграції. Відкликання не вважається безпечним без такого
   блокування; повторне спарювання не успадковує дозволів.

- [x] .NET isolated DLL: Voice parser, локальні grants, Finance routing,

- [x] Pure Java: MAC/UDP magic packet, перевірка /24 та /25 підмереж,
  DER→P1363 підпис, голосові команди до типізованих дій.
- [x] WPF XAML/code: компіляція в **тимчасову DLL**, без Jarvis.Windows.exe.
- [ ] Фізичні Windows/Pixel/Watch7 тести: **не проводилися**.
- [ ] Увімкнення реального Worker: **не проводилося**.
- [ ] Збірки/дистрибуція APK/EXE: **не проводилися**.

Після кожного виправлення повторювати позитивний і негативний випадок. При
відсутності підтвердження показувати «результат невідомий», а не «виконано».

## Повторні сценарії P5 (фізичний Windows; наразі очікують запуску)

- [ ] Вибрати шаблон «Музика». Відкриває Spotify лише після ручного збереження
  та запуску; НЕ запускає пісню автоматично. Вибір шаблону не змінює записані макроси.
- [ ] `app.active:chrome`: Chrome → JARVIS → Chrome. Обидва переходи
  в Chrome мають враховуватися, але cooldown блокує надто частий запуск.
- [ ] Натиснути «Зберегти v2» повторно: ID/LastRun зберігаються; cooldown
  не обнуляється; редагування вмісту не запускає жодної дії.
- [ ] Два макроси на один `HH:mm`: виконати ОБИДВА, не лише перший.
- [ ] Розпочати довгу дію, натиснути STOP: linked CancellationToken
  перериває дію; не запускати наступний крок, показати «скасовано».
- [ ] Увімкнути `network.offline` і `network.online`; перевірити
  зміну під час втрати Wi-Fi, sleep/resume й багаторазових перепідключень.
- [ ] Якщо умова false або автофункції призупинені, не запускати дії.
- [ ] За відсутності інтернету не передавати локальний макрос у ШІ/хмару.

Увага: `NetworkInterface.GetIsNetworkAvailable` визначає доступність
мережевого інтерфейсу, а не гарантує доступ до глобального інтернету.
Умову `інтернет=так` слід вважати приблизною до окремого тесту
реальної мережевої досяжності. Навмисно НЕ відправляємо фонові запити щосекунди.
