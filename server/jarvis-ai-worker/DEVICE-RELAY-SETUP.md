# Зв'язок Pixel ↔ Galaxy Watch7 ↔ Windows через Cloudflare

**Стан:** код і контрактні тести є; робота реальних пристроїв можлива **тільки після окремого розгортання Worker, оновлення Android і ввімкнення дозволів**. Пуш у GitHub сам по собі нічого не вмикає.

## 1. Розгортання Cloudflare Worker (тільки вручну)

Є два способи:

A. Через Windows/термінал із доступом до Cloudflare:

```powershell
cd server/jarvis-ai-worker
npm install
npm test
npx wrangler login
npx wrangler deploy
```

B. Через GitHub Actions: `JARVIS Cloudflare Worker / manual deploy` → Run workflow.
Для способу B потрібно **попередньо самостійно** додати до GitHub Secrets:
- `CLOUDFLARE_API_TOKEN` — токен Cloudflare із правом розгортання Worker + Durable Object
- `CLOUDFLARE_ACCOUNT_ID` — ідентифікатор облікового запису Cloudflare

**Не надсилай ці значення в чат.** Після розгортання перевір, що в секретах Worker лишилися `OPENAI_API_KEY` і `JARVIS_CLIENT_TOKEN`. Самі секрети не входять до GitHub і не повинні додаватися в конфігурацію `wrangler.toml`.

Новий код вмикає Cloudflare Durable Object SQLite `DeviceRelay` з чергою короткочасних команд і таймером видалення записів через ~2 хвилини. `/chat` залишається окремим від `/device/v1/*`.

## 2. Підключення всіх пристроїв

1. **Pixel:** потрібен новий Android APK після окремої команди на збірку. Відкрити JARVIS → «🔗 Дозволити зв'язок JARVIS із комп'ютером та годинником»; увімкнути фонову службу, залишити Google Wearable сервіси.
2. **Watch7:** після оновлення Android застосунку увімкнути пункт `⋮ → 🔗 Керування пристроями`. JARVIS має бути видимим для прийому дистанційних команд із Windows.
3. **Windows:** `JARVIS Windows 0.2.0 Preview` → Налаштування → Cloudflare Worker URL `https://<your-domain>/chat` та `JARVIS_CLIENT_TOKEN` (токен зберігається DPAPI). Ввімкнути «Дозволити з'єднання з Pixel і Watch7», зберегти. На вкладці «Пристрої» перевірити підключення.

Передавання `Windows → Watch7`: Worker → Pixel → Google Wear Data Layer → Watch7. Команди `Watch7 → Windows`: Watch7 → Pixel → Worker → Windows.

## 3. Перевірка

- На Windows: «телефон» → «увімкни пісню [назва]». Pixel виконує у своїй версії Spotify.
- На Windows: «годинник» → «увімкни плейлист [назва]». Watch7 має бути відкритий; Spotify працює на годиннику.
- На Watch7: «комп'ютер» → «відкрий блокнот». Windows дозволяє тільки вибрані локальні команди.
- На Windows: «запиши нотатку Купити хліб» → «покажи нотатки». Обидві операції читають/пишуть **на Pixel**, старі локальні Windows нотатки залишаються в архіві.
- На Windows: «витратив 150 готівка транспорт автобус» → «звіти». Нові записи й звіт походять із зашифрованої бази Pixel. **Якщо немає підтвердження, перевір журнал на Pixel до повторної спроби.**

## 4. Безпека й обмеження

- Усі пристрої наразі використовують **один приватний** `JARVIS_CLIENT_TOKEN`. Це персональна схема, не для публічного багатокористувацького продукту. Для масштабування потрібні окремі device keys та pairing/revoke.
- Мережевий канал використовує HTTPS, **не** наскрізне прикладне шифрування. Командний текст короткочасно зберігається у Cloudflare Durable Object до видалення. Не надсилай паролі/PIN.
- На Windows підтримуються лише наявні команди й дозволені локальні дії. Це **ще не весь** Android набір команд. Немає повноцінного екранного керування Windows, синхронізації офлайн-макросів чи безперервного українського розпізнавання без потрібного мовного пакета.
- Без інтернету або вимкненого Worker **дистанційне** керування та доступ до спільних записів не працюють, але локальні функції пристроїв не повинні ламатися.
- Worker Deploy не змінює Android-пакети, не створює APK і не встановлює нічого на пристрої.

Дивись `windows/QA-WINDOWS-0.2.0.md` і `android/QA-JARVIS-DEVICE-RELAY.md`.
